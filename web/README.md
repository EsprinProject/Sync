# EsprinNemo 网页版

EsprinNemo 的网页客户端，独立仓库 `EsprinProject/Web`。EsprinSync 启动时把本仓库克隆到它的
`web/` 目录（默认 `--web-repo https://github.com/EsprinProject/Web.git`、分支 `main`），
再在根路径 `/` 上托管：页面与 `/styles/*`、`/scripts/*`、`/fonts/*` 以及 PWA 那几件静态资源
都取自那份克隆，本仓库里没有服务端代码，改动推到这里即改动网页版。

界面与桌面版 EsprinNemo 的**现代布局**逐条对应：同一套设计令牌与组件样式
（`tokens.css`、`base.css`、`sidebar.css`、`editor.css`、`overlays.css`、`settings.css`、
`ai.css`、`alom.css`、`radius.css`、`mode.css`、`motion.css` 与桌面版同名同源），
同一个默认布局（不排标题栏、标签页在工作区顶部、工具按钮悬浮在右上角），
同一套交互（自绘下拉、标签拖动排序与中键关闭、右键菜单、圆角滑块、Alom 风格、换肤交叉淡入）；
数据格式也用同一套内嵌元数据注释，因此网页版与桌面客户端可以被同一份同步日志互相认下。

## 本地直接运行

两条路都行，页面里的样式与脚本一律相对引用，从哪个入口进来都取得到：

- **双击 `index.html`**（`file://`）：最省事。本地副本优先 IndexedDB，取不到就自动退回 localStorage
  （`file://` 下常见，设置页「数据与同步」里能看到当前用的是哪一种）；Service Worker 与「安装为应用」
  在 `file://` 下不生效；
- **起一台静态服务器**（PWA 与离线外壳只有这条路上可用）：

```bash
python -m http.server 8686        # 或 npx serve -l 8686
```

然后打开 `http://127.0.0.1:8686/`。

两条路上都没有 `/health` 与 `/sync/*`（它们由 EsprinSync 提供，这里一律 404），客户端据此进入
**本地模式**：界面、本地副本与离线外壳照常，而**同步这整套一概不出现** —— 顶栏没有同步状态入口，
设置里没有「服务器与同步」那一节（该分类在本地模式下叫「数据与存储」），也不会发出任何同步请求。
网页版没有填写服务端地址的入口（地址取自当前站点）：要同步就用 EsprinSync 托管本页 ——
服务端启动时会把本仓库克隆到它的 `web/` 并在根路径托管，那时同步才作为一项功能出现
（自动连接，必要时弹一次可关闭的登录卡片）。字号、图标与品牌字体都随仓库分发，断网时不会退化成字形名。

## 界面与桌面版的一致程度

| 项 | 状态 |
| --- | --- |
| 现代布局（默认） | 一致：无标题栏，标签页在工作区顶部，应用名在侧边栏，工具按钮悬浮右上角，设置页与标签栏各带一个「返回」 |
| 经典布局 | 一致：标题栏 + 标签栏；切换入口在「设置 → 外观 → 界面 → 布局风格」 |
| 外观 | 一致：明暗主题、界面风格（默认 / Alom）、主题色（预设 + 取色器 + 十六进制）、左上角应用名、圆角尺度（滑块四档）、缩放比例（滑块五档 + 自定义比例）、侧边栏收起、换肤交叉淡入与其余动效 |
| 交互 | 一致：自绘下拉（不用原生弹出层）、右键菜单、标签拖动排序 / 中键关闭 / 滚轮横滚、键盘上下键与 Esc；侧边栏「新建」在现代布局下不弹菜单，悬停时从本体旁边滑出副本（本体新建笔记、副本新建待办），经典布局仍弹「新建笔记 / 新建待办 / 导入文件」菜单 |
| 编辑器 | 一致：编辑 / 分屏 / 预览、排版工具栏、实时预览、字符与字数统计、废纸篓只读态 |
| AI 助手 | 面板与行为一致（对话记录、附带范围、附件、流式回答、复制 / 插入 / 存为新笔记、Agent 模式与撤销）；密钥存放与请求路径不同，见下 |
| 秘密本 | 一致：隐藏的条目不进列表 / 搜索 / 统计 / AI 提问范围，只能在「设置 → 秘密本」里找回；设了密码的条目正文以 AES-256-GCM 加密落盘，解锁 / 立即锁定 / 解除密码与桌面版同一套操作，信封格式逐字段对齐（加解密不依赖 WebCrypto，见下） |
| 小本本 | 不提供（桌面版是始终置顶的独立窗口） |
| 字体 | 不提供定制，一律用 `styles/tokens.css` 的默认字体栈 |
| 设置页 | 分类与分区命名对齐桌面版（编辑器 / 外观 / AI 助手 / 数据与同步 / 系统），只留浏览器能落地的项目；离开设置页时连它那一枚「设置」标签一起收掉 |
| 移动端 | 平板与手机上自动改为一栏一层：侧边栏整条收起、列表占满整屏、打开条目后工作区整屏盖上，见下 |

### 手机与平板

样式全部写在 `styles/web.css` 的末尾，分三档递进，桌面端的取值一条都不变：

| 档位 | 变化 |
| --- | --- |
| ≤ 1180px（平板横屏） | 三栏仍然并排，侧边栏 / 列表 / 设置分类侧栏逐档收窄，右侧走廊同步收窄 |
| ≤ 860px（手机与竖屏平板） | 改成一栏一层：侧边栏整条收起（分类筛选改到列表表头、设置与导入改到顶栏右端的菜单里），列表占满整栏，打开条目时工作区整屏盖上并在编辑器顶栏左端给出「返回」；编辑器顶栏各段收窄、分屏改上下两段、正文 16px；AI 助手改成贴底悬浮的半屏卡片；设置页改成两级：先分类列表，点进去才是该分类的面板（面板顶端一条「设置」回到列表） |
| 触摸设备（`pointer: coarse`） | 点击目标放大（按钮 32~36px、卡片与列表项加高），「悬停才出现」的删除、重命名等操作改为常显，输入框一律 ≥ 16px 以免 iOS 在聚焦时把整页放大；**列表卡片不可选中**（`user-select: none` + iOS 的 `-webkit-touch-callout: none`）—— 触摸设备上长按卡片是「打开条目菜单」的手势，不拦的话系统会顺手把标题选上并弹出选择手柄；只拦这一层，正文 / 输入框 / 设置里的路径仍可选中，鼠标环境下列表也照旧可选 |

手机端不只是一份缩窄的桌面排版，另有一层专属界面（结构与行为见 `styles/mobile.css`）：

- **底部主导航**：`笔记 / 待办 / 置顶 / 废纸篓` 四个入口加中间一枚「新建」（按下给一层浅底、**松开时渐隐**：过渡写在基础规则里，`:active` 里改成 `0s` 让按下当场亮起来；选中时图标与文字由灰渐变到主题色，`color` 走 `--motion-base`），与侧边栏那四项是同一套筛选（工作区、设置页与 AI 面板铺开时各自盖住它，设置页自己带「返回」；设置页 / 搜索期间 / AI 面板 / 软键盘弹起时**整条往下滑出让位** —— 位移加负下边距把占位一起收掉，`--motion-base` 过渡，见下文）；
- **搜索期间收起底栏**：搜索框聚焦、或框里已有文字时，底栏整条收起，结果列表整屏铺开；判断交给 CSS（`html:has(#input-search:focus)` 与 `html:has(#input-search:not(:placeholder-shown))`），不经过 JS；
- **底栏上沿的面板**：按底栏中间那枚，底栏上沿向上滑出一块面板 —— 平时二选一：`新建笔记` / `新建待办`；切到废纸篓时同一枚换成「清空」（图标 `delete_forever`，**换字形走一次淡入淡出**：圆底与字形在标记里分成 `.fab-circle` / `.ms-icon` 两层，动的只有里面那层字形，蓝色圆底一点不动），滑开的是 `清空废纸篓`（告警色，确认即执行，不再叠 `showConfirm` 弹窗）/ `取消`；其余画面压一层深色遮罩，点遮罩、按 Esc 或转屏都收回；
- **顶部一条顶栏**：左端是应用名（现代布局下这条本是右上角悬浮按钮组的空壳，窄屏把它重新摊开成一条真顶栏；桌面端应用名在侧边栏顶部，这里另画一份），窄屏的应用名只作展示、不可点；右端是同步状态、AI 助手与一枚「更多」菜单（全屏按钮与深浅色开关在窄屏都收掉 —— 全屏手机浏览器点不动，只能靠「添加到主屏幕」全屏运行，深浅色改从菜单里选）；
- **列表表头：搜索框（窄屏右端带筛选）**：搜索框内右端一枚 `filter_list`（排在清除 × 之后，字形与框内另外两枚同档 16px，按下那层浅底只比字形大 3px（22px 高的方框），右外侧用负外边距吃掉框自身内边距的一半、再靠右一点；当前筛着文件夹 / 标签时点亮成主题色），点它滑开一张与底栏那两张同款的贴底面板：先列文件夹（末行「新建文件夹」），再列标签（当前没有标签就不排这一段），当前生效的那一条带对勾；**正筛着文件夹 / 标签时，面板头一条是「清除筛选」**（`filter_list_off`，选中即回到「全部笔记」，与侧边栏点掉标签同一个去处；底栏那四页不排它 —— 那里没有可清的「分类过滤」）；选一下即换筛选并把列表滚回顶部（`applyMobileFilter`），筛到文件夹 / 标签时按钮点亮成主题色（`renderCounts` 同步 `#btn-list-filter` 的 `.active`，两边共用 `store.js` 的 `isCategoryFilter`）。手机端没有侧边栏，这是分类过滤的唯一入口（四个主入口在底栏里）；**提示文字窄屏不带 `(Ctrl+K)`**（`searchPlaceholderText` 只给正文，快捷键那截由 `render.js` 按档位补）；
- **顶部右端的菜单**：深浅色、设置与导入文件收在一处（桌面端这三件分别在顶栏的图标、侧边栏底栏里）。它与其余菜单共用 `#context-menu`，但在窄屏**走「右键菜单」那种浮层**（`data-menu-kind="topbar"` 从贴底那一套里排除掉：保留 `overlays.css` 的描边 / 圆角 / 投影与 12px 行高，位置按按钮的框算在顶栏下方、右边缘贴屏缘，也不压遮罩，点空白、滚动或转屏直接收掉）；
- **编辑器返回**：窄屏不用标签栏左端那枚「回到首页」，改成编辑器顶栏里、文件夹选择器左边的一枚 `arrow_back`，工作区上方为它留的那一行白也随之省下；顶栏最右端另补一枚 AI 助手入口（工作区整屏铺开时行内够不到右上角的悬浮按钮），面板开着时同样点亮；
- **进出编辑器整块横向滑动**（打开时从右侧滑进、返回列表时往右侧滑出）：关着的工作区不再 `display: none`（那样播不出动效），改成留在渲染树里 `transform: translateX(100%)` 让到屏幕右侧；两态各自的过渡写在 CSS 里 —— 位移两边同一条（`--motion-base`），只有 `visibility` 要区别对待（进入当帧显形，退出拖到滑完再隐身）；**返回那一下**由 `<html>` 上的 `editor-leaving` 只改目标值，滑动期间顶栏与正文各段保持原样（`renderWorkspace` 会问 `isEditorLeaving`），滑完（听 `transitionend`，另留 260ms 兜底）再补一次重绘把它们收起 —— 同一帧就收起的话，滑出去的只是一块空板子；
- **列表上上下拉手势**：拉到顶后再往下拉（≥ 64px）→ 聚焦搜索框（手机上没有 Ctrl+K，搜索靠这一下唤起键盘）；拉到底后再往上拉 → 与底栏中间那枚同义：平时滑出新建面板，废纸篓下换成清空确认（底栏不在场时不接 —— 面板长在底栏上沿）；只在「那一头本来就滚不动」时接，所以列表中间的上下拖动仍是滚列表，横向拉开超过 30px 的交给翻页手势；
- **列表上左右滑动切页（跟手）**：拇指在列表里往左 / 往右划，列表整块跟着手指移，相邻页的卡片此刻也拼好排在旁边（`fillListContainer` 同一套卡片工厂，所以两页长得一样），两页之间有一道竖线与桌面端列表栏之间的分隔线同款（相邻页的 `::before`，贴在朝向当前页的那一侧，跟着一起动）；松手时**滑过 48px 或一页宽的四分之一、或者甩得够快**（最后 100ms 内的速度 > 350px/s，行程短但快也算）就提交 —— 先把剩下那截位移补完，动画收尾后重渲染整页并归位（相邻页显示的正是要换过去的内容，看不出接缝），没滑够就弹回原位；手指中途掉头时相邻页会换成另一侧那一张；到头了还拉有一道阻尼，且会弹回去；次序按底栏 DOM（笔记 → 待办 → 置顶 → 废纸篓），当前筛选是文件夹或标签时整条手势不动作；屏幕左缘 32px 让给浏览器自己的返回手势，输入框与按钮上的横向拖动不算，浮层铺开时遮罩盖住列表，手势也就落不到；换页后列表滚回顶部（`applyMobileFilter`）；
- **底栏点按也带同一套翻页动效**：手指点某一页时按同一底座滑过去（`listPager.slideTo`）—— 先挂上目标那一页的快照、下一帧起步，动画收尾后换页并归位；目标在次序里靠后就从右往左滑进来，当前页是文件夹 / 标签时按「从右侧进来」算；底栏选中态先亮、不等动画收尾；
- **列表项是列表式，不是卡片式**：卡片式（每项一块圆角底、项与项之间留空隙）在手机上费高度也不便扫读，改成整行铺满的列表 —— `.notes-list` 去掉左右内边距与项间距、`.note-card` 去圆角去描边、改用 1px 下边框当分隔线（末行不画），行内仍是标题 / 摘要 / 时间·文件夹，按下给一层浅底；结构与数据一字未改，只在窄屏换皮；窄屏也**不播** `motion.css` 那套「接 `.list-enter` 错开上浮」的列表进场（切页本身已经有一层横向位移，再叠一层会发噪；那套动画仍留给桌面端）；
- **列表项「更多」**：触摸设备没有右键，卡片右上角常显 `more_vert`，长按 500ms 同样打开条目菜单；两者都落到贴在底栏上沿的整块面板（与「新建」面板同一副样子：行高 52px、图标用主题色、不描边不收角；破坏性的那一条（移入废纸篓 / 彻底删除）图标与文字同色 —— 用 `color: inherit` 跟正文保持一致）—— 展开从底栏里往上滑出来、收起再滑回去（两个方向都走过渡，因此窄屏的 `.hidden` 不改 `display`，只切可见性与点击）；层级压在底栏之下（遮罩 289 < 菜单 290 < 底栏 291），收起时整块滑进底栏那一格、被底栏挡住；其余画面压一层深色遮罩（点遮罩收起），底栏本身仍亮着、也仍可点；面板与底栏之间的距离取自 `--mobile-tabbar-height`（`scripts/app.js` 的 `observeTabbarHeight` 实测）加屏底安全区；
- **设置页是两级**：分类不再横排成一条（五个分类一屏放不下，还要左右滑），改成整屏的分类列表 —— 每行一枚图标加分类名、行尾一枚 `chevron_right`，行高 48px、行间一条细线，最上面是一条 48px 标题栏：「← 返回」（回笔记列表）加「设置」；点进去才是该分类的面板，占满整屏，顶端同样是一条 48px 标题栏 —— 左端一枚 `arrow_back` 回分类列表，右端是当前分类的图标与名字（面板里原本那个 20px 大类名因此在窄屏不排出来）。层级写在 `#settings-view` 的 `.is-subpage` 上（`scripts/settings.js` 的 `setSettingsSubpageOpen`），两栏因此永远只排出一栏；切层级只改类名、不重建面板（面板里可能有正在填的内容），每次进设置页都先落回分类列表（`openSettingsTab`）；桌面端两栏并排，这一层类名不参与排版；
- **设置项也不是卡片、字号也不再照搬桌面端**：面板里的设置行与「自定义主题色」那一块与列表同款 —— 圆角、描边、底色与 Alom 风格的投影一并去掉，行与行之间只留一条细线（末行不画），控件自己那圈描边照旧；字号整体压一档（设置项 13.5px、说明 11.5px、段标题 13px，按钮回到 30px 高 —— 触摸档原本把它抬到 36px）；**控件正文仍是 16px**，那是触摸档「防 iOS 聚焦放大整页」那条，不在这一档里动；段的 `gap` 随之归零，段里不是设置项的那些块（段标题、色板、圆角滑块、说明、快捷键表）各自带上边距，靠 `.settings-section > * + *:not(.settings-row)` 一条兜住；
- **秘密本**：加密条目的锁面板居中铺在编辑区上（解锁前不展示正文）；设置页里的秘密本条目与其余设置行同一副样子（去底去框、行间一条细线），动作按钮换行排在正文下方；
- **AI 助手悬浮在下半部**：手机上不再从右侧整屏铺开（那会盖住整块编辑器），改成占屏高四分之三、离屏底一厘米、两侧各 8px 的悬浮卡片，编辑器上半部仍可见；面板之外压一层深色遮罩（点遮罩关闭面板），卡片收起时从下方退出，键盘弹起时整张卡片抬起（并限高，不让关闭键被顶出屏幕）；打开时底栏收起；
- **编辑器底栏**：`编辑 / 分屏 / 预览` 与待办完成在窄屏移到底栏，与保存状态同一行，宽屏自动挪回顶栏；
- **软键盘让位**：`visualViewport` 与布局视口的高度差记进 `--keyboard-inset`，键盘弹起时底栏收起、弹窗与提示条按差值上移。

另外 `viewport` 带上了 `viewport-fit=cover`，整页用 `env(safe-area-inset-*)` 让开刘海与圆角屏的边角，
返回键、AI 面板、弹窗与提示条各自按所在边的安全区让位；在 iOS 上「添加到主屏幕」后按独立应用全屏运行。

窄屏的形态由脚本配合：`scripts/boot.js` 在首屏就不套用「侧边栏收起」，`scripts/app.js` 负责底栏面板、
列表筛选与顶栏菜单的开合（都走同一个 `#context-menu`）以及转屏后的重新判定（`bindBreakpointChange`），
「收起侧边栏」这个桌面偏好不在窄屏生效。

### 界面尺寸（缩放比例）

桌面版改的是 Chromium 的窗口缩放（`webFrame.setZoomFactor`），网页版没有这层能力，改用根元素
（`<html>`）的 CSS `zoom` 近似，设置项在「设置 → 外观 → 界面」：五档取值（80 / 90 / 100 / 110 / 120%）
与「自定义比例」（50 ~ 200 的整数百分比）都与桌面版一致。首屏由 `scripts/boot.js` 在样式表生效前写入，
运行时由 `scripts/app.js` 的 `applyUiScale` 改写，与其余外观项一同存在 localStorage。
它只缩放页面本身，不改浏览器窗口，也会与浏览器自带的缩放叠加；各浏览器对根元素 `zoom`
的实现细节略有差异（视口单位、固定定位层的换算），若某个比例下出现排版溢出，调回 100% 即可恢复。

### 秘密本（隐藏与密码）

- **隐藏**（`isHidden`）：条目仍是一份普通笔记文件，只是不再进任何列表、搜索、统计与 AI 提问范围，
  只能在「设置 → 秘密本」里找到并打开（`scripts/store.js` 的 `getFilteredItems` 与 AI 各入口按它过滤）；
- **密码**（`locked`）：正文以 AES-256-GCM 加密后落盘。落盘只有一条出口（`serializeItemFile` →
  `serializeSecretBody`），因此本地副本与待推送队列里留下的永远是密文；标题、文件夹、标签与时间保持明文。
  解锁后明文与派生密钥只活在当前会话（关闭页面、断开连接或清空本地副本即失效），
  `isHidden` / `isLocked` 两项元数据与桌面版同名同义，同一份文档在两端都能解开；
- **加解密不用 WebCrypto**：`crypto.subtle` 只在安全上下文（`https://` 或 `localhost`）里存在，
  而网页版常年跑在局域网的 http 上，因此 `scripts/secret.js` 里是纯 JS 的 SHA-256 / HMAC / PBKDF2
  与 AES-256-GCM（轮常量、S 盒都按设定算出，不写死表）。25 万轮派生在本机约 0.5 秒，
  界面先让出一帧再开始算，免得弹窗还没画出来就卡住。算错的代价是两端互不开，因此这份实现自带
  自测：在 EsprinSync 仓库里 `node secret-selftest.js`（需已把本仓库克隆到它的 `web/` 下），
  逐个用例与 `node:crypto`（桌面版的实现）对拆，双向都要还原同一份正文；
- **经典脚本的命名空间**：`scripts/*.js` 共享同一个全局作用域，顶层 `const` / `let` 重名会让
  后载入的那一份整份解析失败（`scripts/sync.js` 里另有一份 SHA-256，因此本文件的密码学函数一律带
  `secret` 前缀）。新增脚本时先确认没有重名。

### 浏览器里做不到的部分

- **托盘与驻留后台、开机自启、应用自更新**：都依赖 Electron 主进程。
- **数据存放位置**：浏览器不允许自选存储目录，本地副本存在 IndexedDB（不可用时退回 localStorage）。
- **AI Key 的保管**：桌面版交给系统密钥链、请求由主进程代理；网页版只能由页面直连站点，密钥保存在本浏览器（localStorage），并且可能受站点的 CORS 策略限制。
- **导入文件日志 / 文件日志转为文件夹**：日志重放与目录树导出都要读写本机目录，浏览器里两件都做不到；服务端管理页可以下载 `journal.log`，但网页版不能把它铺成本机的目录树。

## 安装为应用（PWA）

网页版带清单与 Service Worker，可以在手机或桌面上装成独立窗口的应用：

- **清单** `manifest.webmanifest`：名称、`display: standalone`，`start_url` / `scope` / `id` 都是 `/`，
  深色启动底色，三枚图标（192 / 512 / maskable 512）加 iOS 用的 `apple-touch-icon`。
  图标由 `tools/make_pwa_icons.py` 从 `favicon.png` 生成（纯标准库的面积平均缩放，不依赖 Pillow），
  换图标后重跑一次即可；
- **Service Worker** `sw.js`：把界面外壳（首页、样式、脚本、图标、字体）装进版本化缓存 ——
  导航请求网络优先、断网回退到缓存，静态资源 stale-while-revalidate；
  `/sync`、`/admin`、`/health` 一律放给网络，同步与鉴权不经过缓存。
  样式或脚本有增删后把 `CACHE_NAME` 的版本号 +1，旧缓存由 `activate` 清掉；
- **浏览器界面色**：`<meta name="theme-color">` 由 `scripts/app.js` 的 `syncThemeColor` 跟着当前主题改写
  （取标题栏底色），换肤后独立窗口的标题栏 / 状态栏也跟着换；
- **安装**：Android Chrome 用地址栏或菜单里的「安装应用」；iOS Safari 用「分享 → 添加到主屏幕」
  （iOS 认 `apple-touch-icon` 与那几个 `apple-mobile-web-app-*` 标记）。桌面 Chrome / Edge 同样可以安装。

**两条边界**：① Service Worker 与安装提示都只在安全上下文里可用 —— `https://` 或 `localhost`；
用局域网地址（`http://192.168.x.x:8686`）打开时浏览器不给 Service Worker，安装也只会得到一个普通快捷方式
（点开仍是浏览器标签页，`scripts/app.js` 里那一步会直接跳过，不影响其它功能）。
② 离线能打开的只是界面外壳：条目数据本来就在浏览器本地副本里（IndexedDB，断网可读可写），
拉取与推送仍需服务端在线。

## 访问方式

服务端启动后直接访问根路径：

```
http://<服务器地址>:8686/
```

- `/` 返回网页版界面（`/styles/*`、`/scripts/*`、`/fonts/*`、`/favicon.png` 以及 PWA 的
  `/manifest.webmanifest`、`/sw.js` 与 `icon-*.png` 是它的静态资源）；
- `/health` 返回服务端状态 JSON（旧根路径 JSON 响应的去处，含 `passwordSet` / `tokenCount` / `accountCount`）；
- `/sync/*` 为同步接口，`/admin` 为管理后台（`/admin/app.css`、`/admin/app.js`、`/admin/fonts/*` 是它的静态资源，`/admin/api/*` 是它的接口）。

## 存储与鉴权

下面这一节只适用于**由 EsprinSync 托管**的页面：本地模式里没有同步，也就没有这层鉴权。

网页版把**托管它的这台 EsprinSync 直接当存储**：本地只保留一份用于加速启动与断线缓存的副本
（IndexedDB，不可用时退回 localStorage），读写最终都落在服务端的操作日志上；副本按账户各存一份，
见下文「多账户与本地副本」。

启动流程：

1. 先用本地副本渲染首屏；
2. 探测 `/health`，再拿 `/sync/state` 试一次鉴权访问；
3. 通过则自动进入服务端存储：首次使用做一次全量接入（重放服务器日志 + 上传服务器没见过的本地条目），
   之后按设置的节奏增量拉取，本地改动在编辑后立即推送；
4. 被拒则弹出连接层，填入账户名 + 密码或访问令牌后才能读写服务端；这张卡片可以关掉
   （右上角 × / Esc / 点卡片外），关掉就留在本地模式，要再连点顶栏那枚状态 chip。

鉴权有两种方式，同源页面默认走前者：

| 方式 | 说明 |
| --- | --- |
| 账户登录 | 连接层填服务端上的账户名与密码（服务端默认只有 `admin`，其余账户在 `/admin` 的「账户」一节新建），服务端下发 12 小时的同源 Cookie，`/sync` 接口直接复用；服务端同时校验 `Origin` 与 `Host` 是否一致 |
| 访问令牌 | 在 `/admin` 创建，或使用启动参数 `--token` 的值；填写后以 `Authorization: Bearer` 方式访问，保存在浏览器本地存储中 |

服务端对 `/sync/*` 一律要求凭据：未携带登录会话或访问令牌的请求（包括同源请求）都返回 401；
每份凭据只读写它所属账户的那一份日志，换个账户登录看到的就是另一套笔记与待办。
服务端尚未设置管理密码、也没有创建过令牌时，先在 `/admin` 设置密码或创建令牌；
以 `--token` 启动时，则在连接层填写该参数的值。

### 多账户与本地副本

同一台浏览器可能先后登录不同账户，因此**本地副本、待推送队列与同步位置都按账户各存一份**：
IndexedDB 库名与 localStorage 键名带上「账户名 + 服务器地址」的后缀。混用一份的后果不是「多看见
几条」，而是换账户登录时把这个账户的条目当成「服务端从未见过的本地文件」推上去。

- **引导**：先打开上次用的那个账户的副本（首屏仍是本地直出），连上服务端后再以带凭据的
  `/sync/health` 报出的账户为准校正；不一致就换成那个账户自己的副本并重新装载条目。
- **旧版副本的归属**：没有账户概念的那一份先沿用原来的键名与库名，由首个日志身份对得上的账户认领
  （服务端迁到多账户时内置账户的日志身份不变，所以升级上来的浏览器能一次对上，而且不必重放整份日志）；
  日志身份为空（还没同步过）时也认领，那只是继承一个空位置；对不上就一直不认领，它的内容不会被读进别的账户。
- **退出登录**：设置页「数据与同步 → 退出登录」会清空界面上的本地副本并回到连接层，那份副本仍留在
  浏览器里（重新登录同一个账户即原样回来）；下一个登录的人只会看到自己的那一份。
- **同步前的账户校验**：自动同步与推送前会确认服务端认的账户仍是本地副本所属的那一个（结果缓存一分钟），
  不一致时既不推也不拉，并回到连接层要求重新登录 —— 两个标签页分别用不同账户时也不会互相写进对方的日志。
- **共用一台浏览器的边界**：本地副本仍然落在浏览器里，能打开开发者工具的人就能读到它，这与桌面版把数据
  放在本机目录里是同一类风险；要彻底隔离请各自使用独立的浏览器配置（或退出登录后再离开）。

## 数据与同步

- **存储单位**：`notes/{id}.md`、`todos/{id}.md`，与桌面版数据目录里的文件同名同格式
  （内嵌 `<!--EsprinData … -->` 元数据注释），因此两端的哈希一致，可以互推互认。
- **彻底删除后整理日志**：条目被彻底删除后，服务端会把它写过的正文与历史从 `journal.log` 里抹掉，
  只留一行删除标记（别的设备靠它知道这个路径已删除）；序号一个不动，因此按 `seq` 增量拉取的游标照旧有效。
  管理后台的「整理日志」可以把以前积压的旧记录一并清掉。
- **回收 ID**：删除记录里的 ID 会回到回收池；新建条目时向服务端领一个来用
  （`POST /sync/ids/claim`），最近删掉的那一条腾出来的 ID 会重新落到新建的条目上，
  而发起删除的那台设备本地删完就直接用了，不必等一次同步往返。
  领走的 ID 在服务端被占住一会儿（条目落盘即释放，过期自动回到池子），
  且只发给「序号已经跟上、肯定重放过那条删除」的设备（发起删除的那一台除外），
  因此不会出现刚用回收 ID 建的条目被自己还没拉到的删除又擦掉。
- **推送**：本地保存文件后生成 put / del 操作入队，同路径的旧操作被合并，编辑停止 800ms 后推送。
- **拉取**：按 seq 递增应用远端操作；本地有未推送的同路径改动时保留本地（与桌面版 keep-local 策略一致）。
- **首次接入**：重放服务器全部日志（以服务器为准），再上传服务器「从未见过」的本地文件
  （用 `/sync/state` 的现存与删除记录判断，避免把已删除的旧副本重新推上去）。
- **队列**：待推送操作存在浏览器 localStorage（`esprin.nemo.outbox`），断网期间的改动不会丢。
- **状态指示器**：顶栏那枚同步 chip 的形态（连接中 / 需登录 / 未连接 / 同步中 / 同步异常 / 待推送 / 已连接）
  全由 `Sync` 的当前状态推导，不另存一份（本地模式里这枚 chip 不出现）。收尾重绘统一放在 `syncNow` 与 `importLocal` 的 `finally` 里、
  且排在清 `running` 之后 —— 反过来（重绘后清标志）收尾那一次会被判成「同步中」，而此后没人再来重绘，
  chip 就一直停在「同步中」；这两条路径也都兜了 `catch`，意外异常同样会落到「同步异常」而不是留在「同步中」。

## 与桌面版的对应关系

| 能力 | 桌面版 | 网页版 |
| --- | --- | --- |
| 界面 | Electron 渲染层，同套样式 | 同一套样式文件与默认（现代）布局 |
| 存储 | 数据目录中的 `notes/`、`todos/` 文件 | 服务端操作日志（本地副本为缓存） |
| 同步 | `src/main/sync_server.js`（操作日志 + outbox） | `scripts/sync.js`，协议与合并策略一致 |
| 鉴权 | 系统密钥链里的访问令牌 | 账户名 + 密码登录（同源会话）或访问令牌 |
| Markdown | `styles/` + `scripts/markdown.js` | 同一套规则与样式取值 |
| 主题 | 系统 / 深色 / 浅色，界面风格、主题色、圆角、左上角应用名、缩放比例 | 一致（缩放比例落在根元素的 CSS 缩放上，见上文） |
| AI 助手 | 主进程代理请求，密钥在系统密钥链 | 页面直连站点，密钥在本浏览器 |
| 秘密本 | `scripts/secret.js` + node:crypto，会话密钥只存内存 | 同一套信封与操作，加解密由页面自己用纯 JS 完成 |
| 小本本 | 独立置顶窗口 | 不提供（`styles/scratchpad.css` 与 `scripts/scratchpad.js` 已不再被页面引用） |
| 字体 | 下拉选择系统字体 | 不提供定制，一律用 `styles/tokens.css` 的默认字体栈 |
| 移动端 | 窗口自行缩放，无独立形态 | 平板与手机上一栏一层 + 底部主导航（侧边栏收起，分类过滤在列表表头的筛选里，见上文「手机与平板」） |
| 托盘、开机自启、自动更新、数据位置 | Electron 主进程能力 | 不提供（见上文「浏览器里做不到的部分」） |

附：网页版的 AI 对话（`ai_chats/{id}.json`）与小本本内容（`scratchpad.json`）只落在本浏览器的 IndexedDB 里，
**不**进同步队列，因此不会把对话记进服务器的操作日志；笔记与待办的推拉不受影响。

## 离线与外部依赖

页面不向外请求任何资源：图标字形（Material Symbols Rounded）与品牌字（Mohave）随仓库分发，
声明在 `styles/tokens.css` 的 `@font-face` 里；样式在 `styles/`，脚本在 `scripts/`。
因此断网、`file://`、局域网内打开都是一样的界面。

- **更新字体**：从 npm 包 `material-symbols` 取 `material-symbols-rounded.woff2` 覆盖
  `fonts/material-symbols/` 下的同名文件（那份 `rounded.css` 里只有 `@font-face` 与一个类选择器，
  本仓库只取前者，已并入 `styles/tokens.css`）；Mohave 取官方发行的可变字重文件。
  两套字体的许可证（Apache-2.0 / OFL）随文件放在各自目录下；
- **仍然需要网络的两处**：AI 助手要连模型服务端点；接上 EsprinSync 之后的同步、鉴权要连服务端。
  两件都不参与首屏与编辑，断开也不影响记笔记。
